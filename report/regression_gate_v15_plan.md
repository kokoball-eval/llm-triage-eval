# 채택 구성 회귀 게이트 v1.5 라벨 전환 계획 (사전 등록)

> **상태: 재현 점검 실행 전에 확정 (2026-10-15).** 이 문서와 [`gate_criteria_v15.toml`](../gate_criteria_v15.toml)은 v1.5 게이트로 실제 실행 기록을 판정하기 전에 커밋한다. 판정을 본 뒤에는 기준 값·점검 항목·기대 결과를 바꾸지 않는다. 바꿔야 할 이유가 생기면 다음 버전 계획으로 넘기고 그 사실을 기록한다.

## 요약

- **질문** — 채택 구성(qwen2.5:7b + M2)의 회귀 게이트를 v1.5 정답표 기준으로 옮겨도, 같은 구성은 통과시키고 나빠진 구성은 잡아내는가?
- **방법** — 모델을 다시 실행하지 않는다. v1.4 게이트의 기준선 실행 기록(seed 1·11·21)을 그대로 두고, 기준선과 후보를 채점하는 정답표만 v1.4 평가셋에서 v1.5 평가셋으로 바꾼다. 기준 값은 `gate_criteria_v14.toml`과 같다.
- **쓰임** — 이후 프롬프트·방법·안전장치 변경은 `uv run triage-gate --dataset v15`로 판정한다. v1.4 게이트(`--dataset v14`)는 동결하고 이전 판정의 근거로 남긴다.

## 1. 왜 바꾸는가

v1.5 라벨 일치율 검토에서 개발용 33문항의 정답표가 바뀌었다(`data/eval_v15/label_changes_v15.json`). 게이트가 계속 v1.4 정답표로 채점하면, 이후 변경이 "v1.5 기준서로 보면 맞는 답"을 내도 오답으로 세어 회귀로 판정할 수 있다. 반대로 v1.5에서 Critical이 된 B17을 놓쳐도 잡지 못한다.

QA 실무로 보면, 심각도 기준표를 개정한 뒤 **회귀 테스트의 기대 결과(expected result)를 새 기준표에 맞춰 갱신**하는 작업이다. 테스트 케이스(리포트 입력)와 합격 기준(허용 하락 폭)은 그대로 두고 기대 결과만 바꾼다. 부트캠프 Private LLM 트랙에서 다룬 평가 원칙대로 한 번에 하나만 바꾼다. 이번에 바꾸는 것은 정답표 하나다.

## 2. 모델을 다시 실행하지 않는 이유

- v1.4와 v1.5 평가셋은 문항 ID·입력이 완전히 같다(재채점 검증 V0, `report/rescore_v15.md`). 기준선 실행 기록을 v1.5 정답표로 채점한 값이 곧 v1.5 기준선이다.
- 기준선을 모델로 다시 실행하면 응답 자체가 바뀔 수 있다(문항 순서·모델 재로드에 따른 재현성, `docs/issue_log.md` OBS-004·OBS-005). 그러면 정답표와 응답이 동시에 바뀌어 무엇이 기준선을 바꿨는지 구분할 수 없다.
- 후보 실행은 지금처럼 `uv run triage-run --dataset v14 --method m2 --seed <1·11·21> --strict-env`로 만든다. 모델에 들어가는 입력이 같으므로 실행 도구는 바꾸지 않는다.

## 3. 만드는 것

| 파일 | 내용 |
| :--- | :--- |
| `gate_criteria_v15.toml` | `gate_criteria_v14.toml`의 기준 값을 그대로 옮긴다. 다른 점은 `[meta]`에 `labels = "v15"`(채점 정답표)를 더한 것뿐이다(`version = "1.5"`는 v1.4 게이트 기준 파일에도 이미 적혀 있던 게이트 버전이다). 기준선은 v1.4 게이트와 같은 실행 기록 3개를 가리키며 복사하지 않는다 |
| `src/triage_eval/pipeline/gate_v15.py` | v1.4 게이트(`gate_v14.py`)의 seed 짝 맞추기·비교 조건 확인·판정 함수를 그대로 쓰고, 채점 정답표만 v1.5 평가셋으로 바꾼다 |
| `src/triage_eval/pipeline/gate_v14.py` | 정답표·출력 경로·보고서 머리말·기준 파일 키 목록을 인자로 받을 수 있게 한다. 기본값은 지금과 같아 v1.4 게이트의 동작은 바뀌지 않는다 |
| `src/triage_eval/pipeline/gate.py` | `--dataset v15`를 v1.5 게이트로 연결한다 |
| 출력 | `data/results/v15/gate_result_v15.json`, `report/regression_gate_v15.md` (새 파일) |

v1.4 게이트의 기준 파일·판정 결과·보고서(`gate_criteria_v14.toml`, `data/results/v14/gate_result_v14.json`, `report/regression_gate_v14.md`)는 고치지 않는다.

## 4. 판정하지 않는 경우 (안전장치)

v1.4 게이트의 확인(개발용만, seed 3개, 같은 실행 조건, 모델 digest, 실행 도중 재로드)에 다음 두 가지를 더한다. 하나라도 어긋나면 판정하지 않는다(종료 코드 2).

| 확인 | 이유 |
| :--- | :--- |
| v1.5 정답표의 문항 ID·입력·구분이 v1.4 평가셋과 같다 (재채점 도구의 V0 검사를 그대로 사용) | 입력이 다르면 v1.4 실행 기록에 v1.5 정답을 대조할 수 없다 |
| 정답표 파일이 실제로 v1.5 평가셋이다 (`version`, `changed_ids_v15`) | v1.4 파일을 가리키면 위 검사는 통과하므로, 조용히 v1.4 정답표로 판정하게 된다 |
| 기준선·후보 실행 기록의 평가셋 지문(`dataset_sha256`)이 지금 저장소의 v1.4 평가셋과 같다 | 모델이 실제로 본 입력이 v1.5 정답표의 입력과 같음을 실행 기록마다 확인한다 |

## 5. 재현 점검과 기대 결과 (사전 등록)

이 문서를 커밋한 뒤 아래 점검을 실행한다. 기대와 다르면 도구 결함으로 보고 v1.5 게이트를 쓰지 않으며, 원인을 `docs/issue_log.md`에 기록한다. 단, G0에서 6칸 값이 다른 응답 때문에 생긴 문항 단위 변화나 FAIL은 도구 결함이 아니라 응답 차이로 기록하고(어느 응답이 어느 칸에서 달라졌는지 함께 적는다), 이 경우 v1.5 게이트의 기준선 재현 점검은 "응답이 다른 실행"으로 판정한 것임을 결과에 밝힌다.

| 번호 | 점검 | 기대 결과 | 이유 |
| :--- | :--- | :--- | :--- |
| G0 | G1 후보 실행 3개와 기준선의 응답 동일성 — seed마다 같은 (문항, 회차)의 파싱된 6칸 값이 같은지 센다. 정답표를 쓰지 않는 점검이다 | 기록만 한다 | v1.4 게이트의 문항 단위 변화 0은 "v1.4 정답표로 맞고 틀림이 같았다"는 뜻일 뿐, 응답이 같았다는 뜻은 아니다. 오답에서 다른 오답으로 바뀐 응답은 v1.5 정답표에서 변화로 잡힐 수 있다 |
| G1 | v1.4 게이트가 PASS로 판정한 후보 실행 3개(`v14_dev_m2_20261007_113808`, `v14_dev_m2_20261008_212316`, `v14_dev_m2_20261008_212807`)를 v1.5 게이트로 판정 | **PASS**. G0에서 6칸 값이 같은 응답은 문항 단위 변화 0 | 같은 정답표로 양쪽을 채점하므로, 6칸 값이 같은 응답은 정답표가 바뀌어도 맞고 틀림이 같아야 한다 |
| G2 | 체크리스트를 뺀 M0 실행 3개(실험 A)를 v1.5 게이트로 판정 | **FAIL** (X-1 Critical 미상신 증가) | 정답표를 바꾼 뒤에도 게이트가 나빠진 구성을 잡아내는지 확인한다 |
| G3 | v1.4 게이트 테스트 전체 | 그대로 통과 | v1.4 게이트 동작이 바뀌지 않았다는 확인 |

- G1은 기준선 재현 점검이며, 그 판정 결과를 `data/results/v15/gate_result_v15.json`, `report/regression_gate_v15.md`로 남긴다. G0 결과는 그 판정과 함께 기록한다.
- G2의 M0 X-1 누락 수(seed 합계 21 대 M2 14)는 재채점 결과(`report/rescore_v15.md`)에서 이미 공개되었다. 이 점검은 기준 값을 정하는 데 쓰지 않으며, 기준 값은 v1.4 게이트와 같다.
- 실제 실행 기록으로 한 G1·G2 판정은 실행 뒤 회귀 테스트로 고정한다. 이 문서와 함께 커밋하는 테스트는 가짜 모델 실행 기록과 안전장치만 다룬다.

## 6. 다음 단계와의 관계

- 이후 회귀 게이트 명령은 `uv run triage-gate --dataset v15`이다. v1.4 게이트는 이전 판정의 재현용으로만 남긴다.
- LLM-as-judge, 확신도 기반 라우팅 단계의 변경도 이 게이트로 "채택 구성보다 나빠지지 않았는가"를 판정한다.
