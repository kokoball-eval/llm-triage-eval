# v1.0~v1.5 측정 요약 — 지금의 구성이 어떻게 정해졌나

> 이 문서는 v1.0부터 v1.5까지 측정한 내용 가운데 **지금 구성을 이해하는 데 필요한 결정과 숫자**만 모았다.
> 각 단계의 계획·기준 파일·보고서·실행 기록 원본은 저장소 태그 [`v1.5-archive`](https://github.com/kokoball-eval/llm-triage-eval/tree/v1.5-archive)에 그대로 있다.
> 아래 표의 "원본" 열은 그 태그 안의 경로다. 태그 안의 파일은 고치지 않는다.

## 1. 한눈에 보기

| 질문 | 결론 | 근거 숫자 |
| :--- | :--- | :--- |
| 어떤 모델을 쓰나 | `qwen2.5:7b` 유지 | v1.0: `llama3.1:8b`는 단문 리포트에서 없는 결함·PC 사양을 날조. v1.4: `gemma4:12b`·`granite4:tiny-h`는 사전 등록한 교체 규칙 미충족 |
| 판단 기준을 어떻게 전달하나 | 프롬프트(기준서 요약) + **Critical 체크리스트(M2)** | v1.4 개발용 Critical 누락 25 → 17. 판정 예시(M1)는 예시 문구를 베껴 탈락 |
| 형식과 절차는 누가 지키나 | 코드 — 칸 재시도, 폐기 확인, 후처리 안전장치 g2 | 최종 평가용 두 세트(v1.4 25건, v1.5 60건)에서 결함 폐기(X-2) 0건 |
| 정답표는 믿을 만한가 | 외부 QA 2명과의 일치율이 사전 기준 미달 → 기준서 v1.5로 개정 | 처리 칸 일치율 63.5%·55.6%(기준 85%), 불일치 177건 검토 |
| 바뀌면 나빠졌는지 어떻게 아나 | 회귀 게이트(seed 1·11·21 모두 통과해야 PASS) | v1.5 라벨 기준선으로 전환, 재현 점검 기대와 일치 |
| LLM 채점관을 쓸 수 있나 | 미채택(두 가지 모두) | 요약 날조: κ 0.18(기준 0.61). 요약 품질: κ 0.56·검출률 73.3% |
| 자동 등록/검토 큐 라우팅을 쓸 수 있나 | 미채택 | 새 최종 세트에서 위험·날조 응답 56건 중 32건(57.1%)이 검토 없이 통과(기준 50% 이하) |

결론적으로 **지금 구성은 "모델이 1차 판정을 하고, 사람이 모든 응답을 확인한다"는 전제**에서 쓴다. 사람 확인을 줄이는 장치(채점관·라우팅)는 측정했지만 기준을 넘지 못해 채택하지 않았다.

## 2. 채택 구성의 성능

채택 구성(qwen2.5:7b + 프롬프트 v2.3 → 칸 재시도 → M2 → 폐기 확인 → 안전장치 g2)의 성능이다.
두 표 모두 저장소에 남긴 실행 기록을 `uv run triage-eval`로 다시 채점한 값이다.

| 지표 | 개발용 63건 × 6회 (378응답) | 새 최종 평가용 60건 × 6회 (360응답) |
| :--- | ---: | ---: |
| 형식 완전 준수 | 100.0% | 99.7% |
| 처리 정답 | 73.3% | 61.1% |
| 분류 정답 | 65.3% | 73.1% |
| 우선순위 정답 | 62.7% | 61.9% |
| **X-1 Critical 미상신** | **14 / 102** | **19 / 96** |
| X-2 결함을 폐기 | 0 / 258 | 0 / 264 |
| X-3 사람 확인 없이 종결 | 14 / 60 | 15 / 60 |
| 날조 — 규칙 탐지기 | 0 | 0 |
| 날조 — 사람 확인 | (측정 안 함) | 23응답(12묶음) |
| 평균 응답 시간 | 2.27초 | 2.44초 |

- 개발용은 방법과 모델을 고르면서 여러 번 본 문항이고, 최종 평가용은 한 번만 실행한 처음 보는 문항이다. **실제 성능에 가까운 쪽은 오른쪽**이다.
- 가장 무거운 실수인 Critical 미상신이 남아 있다. 이 때문에 사람 확인 전제를 유지한다.
- 날조는 규칙 탐지기가 한 건도 잡지 못했고, 사람이 요약을 직접 확인했을 때 23응답이 나왔다. 규칙 탐지기만으로는 날조를 걸러 낼 수 없다.
- 이 실행 기록은 `데이터/실행기록/`에 있고, 시험(`tests/test_runner.py`)이 위 숫자를 고정한다.

## 4. 남은 한계와 다음 후보

- **Critical 미상신.** 새 최종 세트에서 19/96. 체크리스트의 효과는 개발용에서만 확인됐다.
- **날조 탐지.** 규칙 탐지기와 LLM 채점관 모두 사람 판단과 맞지 않았다. 날조 확인은 사람이 한다.
- **정답표의 흔들림.** 9단계 판정은 기준서와 다른 검토자 판단을 따른 3문항(NA16·NA18·NB11)에 민감했다(빼고 세면 50.0%). 라벨 재검토는 v1.6 후보 V16-2다.
- 다음 후보는 [`문서/기준서_v1.6_후보.md`](../문서/기준서_v1.6_후보.md)에 모은다. 결함과 관찰 기록은 [`문서/결함_기록.md`](../문서/결함_기록.md)에 이어서 쓴다.

## 6. 구조 정리에 대해

v1.5까지는 단계마다 도구·기준 파일·보고서를 새로 만들었다. 측정이 끝난 뒤 저장소를 **지금 구성이 어떻게 생겼고 얼마나 잘 하는지**에 맞춰 다시 정리했다.

- 정리 전 상태 전체는 태그 `v1.5-archive`(커밋 02ec380)에 있다.
- 남긴 데이터는 지금 구성을 시험으로 고정하는 데 쓰는 것뿐이다. 평가셋 4개, 실행 기록 12개, 구조 정리 전 도구가 낸 판정·채점 결과 2개다.
- 회귀 게이트 기준은 `기준/회귀_게이트_기준.toml`로 옮겼다. 기준 값은 그대로이고, 기준선 파일 위치만 바꿨다.
- 정리 전후로 판정이 같다는 점은 시험이 확인한다. 기록 738건 재생, v1.5 게이트 판정 재현, 9단계 360응답 채점 재현이다.
