# 화면 설계 — 트리아지 서비스 인터페이스

서비스 화면의 디자인과 화면별 내용을 정한 문서다. 화면을 바꿀 때는 코드와 함께 이 문서를 최신으로 고치고, 맨 아래 **변경 이력**에 한 줄을 남긴다. 업무 규칙(배정·상태·동기화)은 [서비스 설계](서비스_설계.md)에 있다.

## 1. 원칙

1. **화면은 결과만 보여 준다.** 계산·규칙은 `metrics.py`·`sync.py`·`qa.py` 등 각 영역에 두고, 템플릿은 받은 값을 그린다(AGENTS.md "화면은 얇게").
2. **메뉴 하나는 질문 하나에 답한다.** 홈은 "QA 업무가 지금 어떤가", 내 업무는 "내가 지금 무엇을 처리해야 하나", 대시보드는 "어디서 막혔나", 트리아지 품질은 "모델이 얼마나 맞히나"다. 질문에 답하지 않는 내용은 그 화면에 두지 않는다.
3. **처리로 이끈다.** 해야 할 일 옆에는 그 일을 하는 화면으로 데려가는 버튼을 둔다.
4. **숫자는 분모와 함께, 막힌 곳은 빨갛게.** 비율은 "(1 / 3건)"을 함께 쓰고, 기준 일수를 넘긴 것은 `.late`(빨강)로 표시한다.
5. **휴대폰에서도 쓴다.** 375px 폭에서 가로 스크롤 없이 읽히고, 누르는 곳은 손가락으로 누를 만한 크기다.

## 3. 구성 요소

| 요소 | 모양 | 쓰는 곳 |
| :--- | :--- | :--- |
| 머리 메뉴 (`nav.menu`) | 알약 모양 탭. 마우스를 올리면 초록 테두리·옅은 배경, **지금 있는 메뉴는 `--tint` 배경·초록 테두리·진한 초록 글씨**(`aria-current="page"`) | 모든 화면 머리 |
| BTS 연결 표시 (`a.bts`) | 작은 알약. 연결됨 초록, 일부 실패·읽는 중 노랑, 연결 안 됨 빨강, 언제 읽은 값인지 함께 | 머리 오른쪽, 누르면 홈 |
| 카드 (`.card`) · 칸 배치 (`.grid`) | 흰 바탕·테두리·그림자, 폭에 따라 한 줄에 1~3개 | 홈의 마일스톤·스프린트, 대시보드 |
| 막대 (`table.bars`) | 상태 이름 · 초록 막대 · 건수 | 상태별 건수, 부하 |
| 표 | 머리글 회색, 줄 구분선 | 목록 |
| 배지 (`.badge`) | 초록 원 안의 숫자 | 구역 제목 옆 건수 |
| 버튼 | 알약. 주 버튼은 초록 바탕(`button.primary`, `a.button.primary`), 보조는 흰 바탕 | 처리로 이끄는 동작 |
| 접기 (`details.more`) | 테두리 상자 안 한 줄 제목, 누르면 펼침 | 새 리포트 넣기, 동기화 결과 자세히 |
| 탭 (`nav.tabs`) | 머리 메뉴와 같은 알약 | 붙여넣기 / 링크 가져오기 |
| 단계 표시 (`.steps`) | 옅은 초록 알약과 화살표 | 새 리포트·상세 화면의 진행 단계 |

## 4. 메뉴와 화면

메뉴는 다섯 개다: **홈 · 내 업무 · 리포트 · 대시보드 · 트리아지 품질**. 망 접속 모드(`--lan`)에서는 오른쪽에 [휴대폰 접속]과 [로그아웃]이 더해진다.

| 메뉴 | 주소 | 답하는 질문 | 보이는 것 |
| :--- | :--- | :--- | :--- |
| 홈 | `/` | QA 업무가 지금 어떤가 | [지금 동기화]와 마지막 결과 · 현재 마일스톤(완료율, 상태별 건수, D-day, 다른 마일스톤) · 이번 스프린트(목표 이슈 완료율, 상태별, 넘어온 건수) · **QA Review 이슈 전체**(담당자, 머문 기간과 기준 초과, 할 일: 재현 확인 / 긴급 사인 대기) |
| 내 업무 | `/mine` (`/new` 포함) | 내가 지금 무엇을 처리해야 하나 | **지금 처리할 일**(내 QA Review → [재현 확인하기]·[사인하기], 내 회귀 테스트 → [회귀 테스트 결과 넣기], 검토 대기 리포트 → [8칸 확인하고 등록], 실패 → [살펴보고 다시 시도]; 버튼은 상세 화면의 그 처리 칸 `#qa`·`#review`로 간다) · 접힌 **+ 새 리포트 넣기**(붙여넣기·링크) · **내가 넘긴 이슈**(In Dev·Check, 지금 담당과 머문 기간) |
| 리포트 | `/reports`, `/reports/{번호}` | 접수한 리포트가 어디까지 왔나 | 상태별 목록, 상세(원문·검토·확정 8칸·QA 동작·QA 기록) |
| 대시보드 | `/dashboard` | 어디서 막혔나 | 대응 흐름 4칸과 병목 · 구성원별·팀별 부하 · 회귀 테스트(재오픈률·대기 시간) · 스프린트 이월(넘어온 건수, 2회 이상 이월) |
| 트리아지 품질 | `/triage` | 모델이 얼마나 맞히나 | 기간별 사람 수정 비율, Critical 올림·내림, 사람이 바꾼 배정, 처리 시간, 자동 처리율, 실패, 유입·분포 |

- 홈의 QA Review 표와 마일스톤 카드는 고른 마일스톤의 BTS 티켓(서비스가 등록하지 않은 이슈 포함)으로 센다. 마일스톤이 없는 티켓은 보이지 않는다. 다섯 상태 밖의 이름이 있으면 마일스톤 카드에 노랗게 알린다.
- 내 업무의 검토 대기·실패 리포트는 이 서비스의 리포트 전체다(한 사람이 쓰는 전제, 사람별 계정은 다음 단계).
- 예전 주소 `/qa`(QA 보드)는 홈으로 넘긴다. [지금 동기화]는 끝나면 홈으로 돌아간다.
- `/new`(새 리포트)는 링크 미리보기와 입력 오류를 다시 그릴 때 쓰고(`/fetch`, 입력 오류의 `/reports` 포함), 그때도 메뉴는 내 업무가 켜진다.
- 로그인 화면은 메뉴와 BTS 연결 표시를 숨긴다. 사람별 로그인이면 로그인 이름과 비밀번호를, 공용 시연 비밀번호면 비밀번호만 받는다.
- 로그인하면 머리 오른쪽에 `이름 · 역할`(리더/실무자)과 [로그아웃]이 보인다. 상세 화면의 QA 기록 표에는 **실행**(누른 사람) 칸이, 등록 정보에는 등록한 사람이 보인다.

## 5. 변경 이력

| 날짜 | 바뀐 것 | 이유 |
| :--- | :--- | :--- |
| 2026-11-26 | 문서를 만들고 지금 디자인(색·구성 요소)을 기록. 머리 메뉴를 알약 탭으로 바꾸고 지금 있는 메뉴 표시(`aria-current`)를 붙임. 메뉴를 7개(리포트·새 리포트·QA·내 담당·대시보드·트리아지 품질·휴대폰 접속)에서 5개로 줄임. 홈을 QA 업무 현황만으로(입구 카드·최근 리포트 제거, QA Review 표 추가), 내 담당을 내 업무로(지금 처리할 일과 처리 버튼, 새 리포트 넣기 포함), QA 보드는 홈·내 업무로 나눠 옮김, 대시보드는 홈과 겹치는 마일스톤·스프린트 요약을 빼고 분석 전용으로 | 보여 주는 내용이 많아 무엇을 봐야 할지 흐려졌고, 메뉴를 누를 수 있는지와 지금 위치가 보이지 않았다(경민 요청) |
