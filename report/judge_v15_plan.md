# v1.5 LLM-as-judge 측정 계획 — 요약 날조 판정 (사전 등록)

> **상태: 사람 채점과 채점관 측정 전에 확정 (2026-10-15).** 이 문서, [`judge_v15.toml`](../judge_v15.toml), 측정 세트·정답 대응표·개발용 자료와 생성 도구는 검토자가 채점하기 전에 커밋한다. 채점관(LLM) 프롬프트는 §5 절차로 개발용 자료에서만 다듬고, 확정해 커밋한 뒤 측정 세트로 한 번만 측정한다. 결과를 본 뒤에는 기준·측정 세트·프롬프트·실패 처리 규칙을 바꾸지 않는다.

## 요약

- **질문** — 모델 응답의 `[요약]`에 리포트 원문에 없는 내용이 들어갔는지(날조)를 로컬 LLM(gemma4:12b)이 판정하면, QA 실무자의 판정과 얼마나 같은가?
- **방법** — 저장된 실행 기록에서 고른 요약 43건과, 원문에 없는 사실을 일부러 넣은 요약 20건(결함 주입)을 섞은 63건(리포트당 1건)을 검토자와 채점관이 각각 판정한다. 모델은 새로 실행하지 않는다.
- **쓰임** — 기준을 충족하면 채점관의 날조 판정을 확신도 기반 라우팅의 "사람 검토" 신호로 쓴다. 충족하지 못하면 쓰지 않는다.

## 1. 왜 재는가

v1.2의 날조 탐지기(`detect_hallucination.py`)는 기기 모델·수치·날짜처럼 **구체 사실**이 원문에 있는지를 규칙으로 대조한다. "전투 중 캐릭터가 무한히 이동"처럼 **현상 자체를 지어낸 경우**는 구체 사실이 없으면 잡지 못한다(`docs/issue_log.md`의 알려진 한계). 의미 수준의 판정은 규칙으로 하기 어려워 LLM에게 맡기는 방법(LLM-as-judge)이 흔히 쓰이지만, 채점관의 판정이 사람과 다르면 그 숫자를 믿을 수 없다. 그래서 채점관을 쓰기 전에 사람 판정과의 일치를 먼저 잰다.

QA 실무로 보면, 자동화 테스트 도구를 도입하기 전에 **수동 판정 결과와 도구 판정 결과를 대조해 도구의 오탐·미탐을 확인하는 검증 절차**다. 결함 주입(fault seeding)은 테스트가 "있는 결함을 잡는가"를 확인하려고 일부러 결함을 심는 방법으로, 자연 응답에 날조가 드물어도 놓침을 잴 수 있게 한다.

## 2. 날조의 정의 (검토자와 채점관에게 같은 문구로 준다)

- 요약에 리포트 원문(게시판·게시 일시·제목·본문·업데이트 공지·기존 등록 이슈)에 **없거나 원문과 어긋나는 사실 진술**이 하나라도 있으면 **날조 있음**이다.
- 원문을 다른 말로 바꿔 쓴 것, 원문 내용을 줄인 것은 날조가 아니다.
- "~로 추정", "~일 수 있음"처럼 추정임을 밝힌 표현은 날조가 아니다(v1.2 탐지기의 hedged 규칙과 같다).
- 판정은 **날조 있음 / 날조 없음** 둘 중 하나다. 있음이면 해당 문구를 적는다.

## 3. 측정 세트 (63건, 리포트당 1건)

| 구분 | 건수 | 출처 | 이유 |
| :--- | ---: | :--- | :--- |
| 자연 응답 | 43 | qwen2.5:7b의 세 구성(M2 채택 구성·M0·M1) seed 1 실행 1회차에서, 리포트마다 고정 seed로 한 구성의 요약을 고름 | 실제로 라우팅이 받을 응답과, 요약 방식이 조금 다른 응답을 함께 본다 |
| 결함 주입 | 20 | 채택 구성 seed 1 1회차 요약에, 원문에 없는 사실을 요약 문장 안에 녹여 씀 | 놓침(미탐)을 확실히 잰다 |

- **리포트당 1건** — 개발용 리포트 63개가 모두 한 번씩만 나온다. 같은 리포트가 여러 번 나오면 등장 횟수나 두 요약의 비교가 주입의 단서가 된다(처음 설계한 100건 세트에서 독립 검토로 확인하고 바꿨다).
- **채점관이 쓴 요약은 넣지 않는다** — 채점관 gemma4:12b가 쓴 요약(실험 B)을 넣으면 자기 응답을 자기가 채점하는 편향이 생긴다.
- **주입 문장** — 기기(4)·수치(4)·시점(3)·추가 현상(5)·원인 단정(4) 다섯 종류 20건이다. 대상 문항은 고정 seed로 정했고, 각 요약의 내용·말투에 맞게 원문에 없는 사실을 요약 문장 안에 녹여 썼다(`tools/judge_v15/build_set.py`의 `INJECTIONS`). 넣은 사실의 핵심어가 그 문항의 원문과 원래 요약에 없는지 생성할 때마다 확인한다. 기기·수치·시점은 v1.2 탐지기도 잡을 수 있는 구체 사실이고, 추가 현상·원인 단정은 탐지기가 잡지 못하는 의미 수준 날조다.
  - 원래 요약부터 원문과 어긋나는 문항 1건, 주입한 원인이 원문의 함의로 읽힐 수 있는 문항 2건은 처음 고른 대상에서 뺐다. 정답이 모호한 주입은 20건 중 1~2건으로 판정을 가를 수 있기 때문이다.
- **블라인드** — 세트는 J01~J63으로 섞는다. 채점 시트에는 리포트 원문과 요약만 넣고, 문항 ID·구성·주입 여부는 넣지 않는다. 정답 대응표(`answer_key_v15.json`), 개발용 자료(`dev_set_v15.json`), 주입 문장이 적힌 생성 도구(`tools/judge_v15/build_set.py`)는 저장소에 두되, 검토자는 채점을 마칠 때까지 열지 않는다.
- 최종 평가용 25건은 쓰지 않는다. 정답 라벨은 쓰지 않고 바꾸지도 않는다.
- 측정 세트·대응표·개발용 자료는 봉인한다. 생성 도구는 이미 있는 파일과 내용이 다르면 쓰지 않는다.

## 4. 판정하는 사람과 채점관

| 항목 | 내용 |
| :--- | :--- |
| 사람 채점 | 검토자 1명(게임 QA 8년). 채점관의 판정을 보기 전에 채점 시트를 제출한다. 판정 칸이 하나라도 비면 계산하지 않고 채워서 다시 받는다 |
| 채점관 | gemma4:12b(로컬, Ollama). 측정 세트에 이 모델이 쓴 요약은 없다. temperature 0, seed 1. 모델 digest를 기록한다 |
| 채점관 입력 | 검토자 시트와 같은 칸: 입력 종류·게시판/작성자·게시 일시·제목·본문·업데이트 공지·기존 등록 이슈·요약, §2 정의 |
| 참고 | v1.2 날조 탐지기의 판정도 같은 63건에 대해 기록한다(판정 기준에는 쓰지 않음) |

**채점관 실행의 실패 처리 (사전 등록)**

- 출력을 읽지 못하면 같은 입력으로 1번 다시 요청한다. 그래도 읽지 못하면 그 건은 **검토자와 불일치**로 세고, 주입 건이면 **놓침**으로 센다(가장 불리하게 처리). 건수는 결과에 적는다.
- 실행 도중 모델이 다시 로드되면(OBS-005) 그 측정은 판정하지 않는다. 측정 환경을 정리한 뒤 같은 프롬프트로 처음부터 다시 측정한다. 이것은 결과를 보고 다시 재는 것이 아니라 측정 환경 오염을 걸러 내는 것이며, 다시 잰 사실과 이유를 기록한다.

## 5. 채점관 프롬프트 확정 절차

1. **개발용 자료** — 채택 구성 기준선 seed 11의 1회차 응답에서, 측정 세트와 글자까지 같은 (리포트, 요약)을 뺀 49건. 그중 10건에 측정 세트와 다른 개발용 주입 문장을 넣었다(`dev_set_v15.json`). 개발용 주입 대상은 측정용 주입 문항과 겹치지 않는다.
2. 개발용 자료로만 프롬프트를 다듬는다. 고치는 범위는 출력 형식 오류와 정의(§2)와 명백히 어긋나는 판정이다. 검토자의 채점과 측정 세트에 대한 채점관 판정은 보지 않는다.
3. 확정한 프롬프트와 측정 도구를 커밋하고, 검토자의 채점 시트도 이때 저장소에 보관한다.
4. 측정 세트로 한 번만 측정한다.

## 6. 지표와 판단 기준 (사전 등록)

| 지표 | 계산 | 기준 | 이유 |
| :--- | :--- | :--- | :--- |
| 자연 응답 일치율 | 자연 43건 중 검토자와 채점관의 판정이 같은 비율 | 90% 이상 (39건 이상) | 판정이 둘뿐이라 우연 일치가 커서 라벨 일치율(85%)보다 엄하게 둔다 |
| 자연 응답 κ | 검토자 대 채점관 Cohen κ | 0.61 이상 | 우연 일치를 뺀 일치도. 0.61은 "상당한 일치"의 시작(Landis·Koch, 1977) |
| 주입 날조 검출률 | 주입 20건 중 채점관이 **날조 있음으로 판정하고, 지목한 문구에 주입 핵심어가 들어 있는** 비율 | 90% 이상 (18건 이상) | 날조를 놓치면 라우팅이 위험한 응답을 자동 처리한다. 다른 곳을 지목해 우연히 맞힌 경우는 검출로 세지 않는다 |
| 거짓 경보율 | 자연 응답 중 검토자가 없음으로 본 것 가운데 채점관이 있음으로 본 비율 | 10% 이하 | 과하게 잡으면 검토 큐가 넘쳐 라우팅의 의미가 없어진다 |
| 기록: 자연 응답 검출 | 검토자가 있음으로 본 자연 응답 중 채점관도 있음으로 본 건수 | 판정에 쓰지 않음 | κ를 판정에 쓰지 못할 때도 자연 응답의 놓침을 드러낸다 |
| 기록: 주입 검출(문구 무관) | 주입 20건 중 채점관이 있음으로 본 비율(지목 문구와 무관) | 판정에 쓰지 않음 | 위 검출률과의 차이로 "다른 곳을 지목한" 경우를 보여 준다 |
| 기록: 검토자의 주입 검출률 | 주입 20건 중 검토자가 있음으로 본 비율 | 판정에 쓰지 않음 | 사람 채점 자체가 얼마나 믿을 만한지 보여 준다 |
| 기록: v1.2 탐지기 | 같은 63건의 탐지기 판정과 위 지표 | 판정에 쓰지 않음 | 규칙 기반 탐지기와 비교해 채점관이 더하는 몫을 본다 |

- **경계값** — 기준은 모두 "이상/이하"이며, 기준값과 같으면 **충족**이다.
- **κ 판정 생략 조건** — 검토자가 자연 응답에서 날조 있음으로 본 건이 5건 미만이면, κ는 표본이 작아 흔들리므로 기록만 하고 판정에 쓰지 않는다. 이때 자연 응답의 놓침은 주입 날조 검출률이 대신 잰다(주입 날조는 날조가 있는 것이 확실한 표본이다).
- **판정** — 판정에 쓰는 지표가 모두 기준을 충족하면 **채택**, 하나라도 충족하지 못하면 **미채택**이다.

## 7. 결과에 따른 처리 (사전 등록)

| 결과 | 처리 |
| :--- | :--- |
| 채택 | 채점관의 날조 판정을 라우팅의 사람 검토 신호로 쓴다. 채점 보고서에는 참고 지표로 넣는다. 회귀 게이트 기준으로 넣는 것은 별도 계획으로 정한다 |
| 미채택 | 채점관을 라우팅에 쓰지 않는다. 어느 종류(주입 유형, 자연 응답의 어떤 경우)에서 어긋났는지 기록하고 다음 버전에서 다룬다 |
| 자연 응답 일치율이 기준 ±3%p 안 | 판정은 그대로 내리되, 외부 QA 1명이 같은 세트를 채점해 사람끼리의 일치도를 확인할 후보로 기록한다 |

## 8. 한계

- **사람 채점자가 1명이고, 정답 라벨을 만든 검토자다.** 이번 채점은 라벨이 아니라 요약 품질이라 라벨 편향의 영향은 작지만, 사람끼리의 일치도는 재지 못한다(§7 마지막 행).
- **주입 날조는 실제 날조와 모양이 다를 수 있다.** 주입 검출률은 "있는 날조를 잡는 능력"의 근사다. 그래서 자연 응답 지표와 따로 본다.
- **주입 요약에 겉모양 단서가 남는다.** 사실을 덧붙이는 방식이라 주입 요약이 더 길다(평균 39자 대 25자, 길이만으로 가렸을 때 AUC 0.86). 숫자가 들어간 비율도 주입 45%, 자연 12%다(수치 주입과 숫자가 있는 원래 요약 때문). 쉼표 단서는 주입 방식을 바꿔 줄였다(10% 대 2%). 채점관은 한 건씩 판정하므로 영향이 작지만, 검토자는 무의식적으로 이 단서를 쓸 수 있다. 검토자의 주입 검출률을 "사람 판정의 상한에 가까운 값"으로 해석한다.
- **개발용 자료와 측정 세트가 같은 리포트를 쓴다.** 리포트가 63개뿐이라 피할 수 없다. 대신 글자까지 같은 요약은 개발용에서 뺐고, 개발용 주입 대상은 측정용 주입 문항과 겹치지 않는다.
- **요약 한 칸만 본다.** `[누락 정보 및 권장 조치]`의 요청·권장 반영은 다음 대상으로 남긴다.
- **채점관 모델 하나만 잰다.** 다른 채점관 모델과의 비교는 하지 않는다(한 번에 하나만 바꾼다).
- **자연 응답이 43건이다.** 일치율 1건이 약 2.3%p다. 그래서 기준 근처 결과는 §7 마지막 행으로 따로 표시한다.
