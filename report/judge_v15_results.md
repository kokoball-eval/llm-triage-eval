## 요약

- **판정: 미채택.** 채점관(gemma4:12b)과 검토자의 판정이 자연 응답 42건 중 36건 같았다(85.71%, 기준 90% 이상). 우연 일치를 뺀 일치도 κ는 0.18이다(기준 0.61 이상). 일부러 심은 날조 20건 중 19건은 정확한 문구까지 짚어 잡았고(95%, 기준 90% 이상), 날조가 없는 요약을 날조로 본 비율은 5.41%였다(기준 10% 이하). 사전 등록한 처리(계획 §7)에 따라 **이 채점관은 라우팅에 쓰지 않는다.**
- **(결과를 본 뒤 받은 검토자 의견에 기댄 해석) 어긋난 곳의 상당 부분은 사람 판정 쪽에 있었을 가능성이 있다.** 검토자가 날조로 본 자연 응답 4건 중 3건은 근거가 "오해의 소지·핵심 누락·요약의 방향"으로, 계획 §2의 날조 정의(원문에 없거나 어긋나는 사실)보다 넓은 요약 품질 기준이었고, 1건은 원문을 잘못 읽은 것이었다. 검토자가 놓친 심은 날조 6건 중 2건은 지금 보면 날조가 맞다고, 4건은 대조 때 못 봤다고 답했다. 이 의견은 검토자가 자기 판정의 갈림을 결과를 본 뒤 다시 본 것이므로 판정을 바꾸는 근거로 쓰지 않는다(§5).
- **측정은 재현되었다.** 측정 1회차가 결과 저장 전에 멈춰 2회차를 측정 결과로 썼다. 두 회차가 겹치는 40건의 채점관 판정과 지목 문구는 모두 같았다(§4).

## 1. 무엇을 왜 쟀나

트리아지 모델은 리포트마다 한 줄 요약을 쓴다. 요약에 원문에 없는 사실이 들어가면(날조), 그 요약만 보고 판단하는 개발자나 QA가 잘못된 조치를 하게 된다. 다음 단계인 확신도 기반 라우팅은 "사람이 볼 필요가 없는 건"을 자동 처리하는 구조이므로, 날조가 의심되는 요약을 사람 검토로 보낼 신호가 필요하다.

그 신호를 사람이 매번 만들 수는 없으므로, **다른 LLM(채점관)이 요약을 원문과 대조해 날조 여부를 판정하게 하고, 그 판정이 사람 판정과 얼마나 같은지**를 쟀다. 같다면 채점관을 사람 검토의 신호로 쓰고, 다르면 쓰지 않는다. 기준과 처리는 결과를 보기 전에 정했다(계획 §6·§7).

## 2. 어떻게 쟀나

| 항목 | 내용 |
| :--- | :--- |
| 측정 세트 | 개발용 리포트 63개에 요약을 하나씩(63건). 실제 모델(qwen2.5:7b)이 쓴 요약 43건과, 원문에 없는 사실을 일부러 심은 요약 20건(기기·수치·시점·추가 현상·원인 단정). 채점관 모델이 쓴 요약은 넣지 않았다(자기 글을 자기가 채점하는 편향 방지) |
| 사람 판정 | 정답 라벨을 만든 검토자 1명. 번호(J01~J63)만 보이고 어느 요약이 심은 것인지는 알리지 않은 채 판정. 다만 측정 전 노출로 3건이 자연 응답임을 알 수 있었고, 문항을 보여 준 Claude는 심은 문항을 알고 있었다(§6) |
| 채점관 | gemma4:12b (로컬), 프롬프트 j1, temperature 0·seed 1, 판정과 날조 문구를 JSON으로 출력 |
| 지표 | 자연 응답 일치율·κ(사람과 같은가), 심은 날조 검출률(지목 문구에 심은 핵심어가 있을 때만 검출로 셈), 거짓 경보율 |
| 제외 | A06(J43)은 측정 전에 검토자에게 내용이 노출되어 자연 응답 지표에서 뺐다(42건, [ISSUE-012](../docs/issue_log.md#issue-012)) |

### 채점관 프롬프트를 정한 과정 (검토자 채점이 끝날 때까지 공개를 미룬 내용)

프롬프트는 측정 세트와 다른 실행 기록(seed 11)에서 만든 개발용 자료 49건(자연 39, 심은 날조 10)으로만 다듬었다. 측정 세트에 맞춰 프롬프트를 고치는 일을 막기 위해서다(계획 §5).

- **j1** — 날조 정의(계획 §2)와 "요약을 진술 단위로 나눠 각각 원문에서 찾는다"는 판정 방법을 넣었다. 개발용 자료에서 출력 형식 오류 0건, 심은 날조 10건 모두 맞는 문구로 검출. 자연 응답 39건 중 3건을 날조로 지목했다.
- **j2** — 판정 방법 문장을 하나 더 넣어 보았으나 개발용 판정이 j1과 같았다. 같은 결과라면 문장이 적은 쪽이 개발용 자료에 덜 맞춰진 것이므로 j1을 확정했다. j1을 다시 실행해 같은 결과가 나오는 것도 확인했다. j2 시험과 j1 재실행의 출력은 파일로 남기지 않았고(개발 중 대화 기록에만 있음), 저장소에는 확정한 j1의 개발용 결과(`data/judge_v15/dev_result_v15.json`)만 있다.
- 개발 중 Claude가 개발용 요약을 직접 검토하다, 채점관이 놓친 1건(A06 — 원문의 "성장 지원 패키지"를 요약이 "추석 패키지"로 씀)을 찾았다. 이 내용을 채점 중이던 검토자에게 전달한 것이 ISSUE-012다.

## 4. 측정이 믿을 만한가

- **1회차 중단과 2회차** — 1회차는 채점관 판정 63건을 마친 뒤 결과를 화면에 출력하다 Windows 콘솔 인코딩 오류로 멈춰 결과가 저장되지 않았다([ISSUE-014](../docs/issue_log.md#issue-014)). 출력 순서와 인코딩을 고치고, "2회차를 결과로 쓰고, 달라도 다시 실행하지 않는다"는 규칙을 2회차 전에 등록했다(계획 §14).
- **재현** — 1회차에 화면에 남은 J24~J63 40건의 채점관 판정·지목 문구가 2회차와 모두 같았다. 2회차는 실행 전후 모델 digest가 같았고(6114515d63c1), 실행 도중 모델 재로드 0건, 읽지 못한 출력 0건이다.
- **사람 판정의 기록** — 검토자 판정은 1회차 전에 커밋되어 있어 결과를 보고 바뀔 수 없다. 대화로 문항을 보여 줄 때 9건의 글자를 잘못 옮긴 일(요약 2건, [ISSUE-013](../docs/issue_log.md#issue-013))은 측정 전에 기록했고, 측정에는 처음 채점한 답을 썼다(계획 §13).

## 5. 왜 어긋났나 — 검토자 사후 의견

결과를 본 뒤, 판정이 갈린 문항과 검토자가 놓친 심은 날조를 원문과 함께 다시 보여 주고 이유를 물었다(기록 [`post_hoc_rater_notes_v15.json`](../data/judge_v15/post_hoc_rater_notes_v15.json), 이번에 원문과 함께 물은 11건은 측정 세트와 글자까지 같음을 대조해 그 결과도 기록에 남김. J29는 채점 때 남긴 메모를 그대로 옮겨 기록은 12건). **판정과 지표는 바꾸지 않는다.**

| 갈린 유형 | 문항 | 검토자 사후 의견 요지 | 해석 |
| :--- | :--- | :--- | :--- |
| 검토자만 날조 (자연 4건) | J13 | 오해의 소지가 있는 요약 | **요약 품질**(오해 소지·핵심 누락·방향)을 근거로 판정. 계획 §2 정의보다 넓은 기준 |
| | J29 | (채점 때 메모) 어디 입장 횟수인지 표기 안 함 | 같은 유형 |
| | J37 | 편의성 개선 제보를 기능 누락 오류처럼 요약 | 같은 유형 |
| | J28 | "세 번째 레이드"를 잘못 읽었으나, 오해 소지가 있어 더 정확한 표현이 필요 | 채점 때 원문을 잘못 읽음(이후 근거는 요약 품질) |
| 채점관만 날조 (자연 2건) | J03 | 일반 SSR은 1장 나왔으므로 날조가 있다고 볼 수 있음 | 채점관 쪽에 동의 → 검토자가 놓친 자연 날조 |
| | J10 | 동의 안 함 | 채점관의 거짓 경보 |
| 검토자가 놓친 심은 날조 (6건) | J31·J32·J53·J63 | 대조 때 못 봄 | 사람의 대조 누락 |
| | J14·J19 | 지금 보면 날조가 맞음 | 놓친 이유는 답하지 않음 |

정리하면, 자연 응답의 갈림 6건 중 5건은 사람 판정 쪽 사정이다. 3건(J13·J29·J37)은 날조 정의와 다른 기준(요약 품질)을 썼고, 1건(J28)은 원문을 잘못 읽었고, 1건(J03)은 날조를 놓쳤다. 채점관 쪽의 명확한 오류로 남는 것은 J10 1건이다. 심은 날조에서도 사람(14/20)이 채점관(19/20)보다 많이 놓쳤다. **이번 미채택은 "채점관이 사람과 다르다"를 보여 주지만, 그 차이의 상당 부분은 기준이 된 사람 판정 1명분의 흔들림에서 왔을 가능성이 크다.** 이 해석은 결과를 본 뒤 받은 의견에 기대고 있으므로, 같은 세트로 다시 판정하지 않고 다음 버전의 측정 설계로 넘긴다(§7).

### 검토자 확신도는 갈림을 예측하지 못했다

검토자는 63건 중 62건을 확신도 "높음"으로 답했고, 채점관과 판정이 갈린 11건(자연 응답 6건, 심은 날조 5건)도 모두 "높음"이었다. 사람이 스스로 매긴 확신도로는 "어느 판정을 다시 볼지"를 고를 수 없었다는 뜻이다. 다음 단계인 확신도 기반 라우팅에서 확신도를 무엇으로 잴지 정할 때 참고한다.

## 6. 한계

- **사람 채점자가 1명이다.** 이번 결과의 가장 큰 한계다. 사람끼리의 일치도를 모르므로, 85.71%가 채점관의 한계인지 기준 판정의 흔들림인지 수치로 나눌 수 없다.
- **사후 의견은 결과를 본 뒤 받았다.** 검토자가 자기 판정과 채점관 판정의 갈림을 본 뒤 답한 것이고, 심은 문항은 심은 문구를 『』로 표시해 보여 주었다. §5의 해석은 참고이며, 판정을 바꾸는 근거가 아니다.
- **블라인드가 완전하지 않았다.** 측정 전 노출로 검토자는 3건이 자연 응답임을 알 수 있었고(계획 §8·§11, [ISSUE-012](../docs/issue_log.md#issue-012)), 채점 때 문항을 보여 주고 답을 받은 Claude는 심은 문항을 알고 있었다(계획 §8·§12). 보여 준 내용을 원문으로 제한하고 답에 반응하지 않는 규칙을 두었지만 영향이 없었다고 증명할 수는 없다.
- **심은 날조는 실제 날조와 모양이 다를 수 있다.** 심은 요약이 더 길고 숫자가 많다(계획 §8). 검출률 95%는 "있는 날조를 잡는 능력"의 근사다.
- **세트가 작다.** 자연 응답 1건이 일치율 약 2.4%p이고, κ는 날조 5건에 크게 흔들린다.
- **같은 세트는 다시 쓰지 않는다.** 결과와 사후 의견을 모두 본 세트이므로, 다시 잰다면 새 세트로 잰다.

## 7. 다음 버전 과제

1. **사람 채점자 2명 이상과 채점 전 정의 맞추기** — 날조 정의를 예시와 함께 먼저 맞춘 뒤 채점하고, 사람끼리의 일치도를 함께 잰다(계획 §7의 외부 QA 후보와 같은 방향).
2. **날조와 요약 품질을 다른 지표로 나누기** — 검토자가 날조로 본 4건의 근거(오해 소지·핵심 누락·방향)는 그 자체로 중요한 결함이다. 바로 다음 단계에서 요약 품질을 별도 기준으로 정해 사람 채점·채점관 일치율을 잰다.
3. **채점 화면으로 판정 받기** — 원문을 옮겨 적다 생긴 오류(ISSUE-013)를 없애고, 질문 방식이 판정에 주는 영향도 줄인다.
4. **새 측정 세트** — 이번 63건은 결과를 본 세트이므로 다음 측정에는 쓰지 않는다.
