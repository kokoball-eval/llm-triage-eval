# v1.5 요약 품질 LLM-as-judge 계획 (사전 등록)

> 기준 [`quality_v15.toml`](../quality_v15.toml) · 세트 생성 [`tools/quality_v15/build_set.py`](../tools/quality_v15/build_set.py) · 채점 화면 [`tools/quality_v15/rater_server.py`](../tools/quality_v15/rater_server.py)
> 검토자 채점과 채점관 측정 전에 확정한다(2026-10-29). 결과를 본 뒤 이 문서의 정의·기준·처리를 바꾸지 않는다. 바꿀 일이 생기면 추가 기록으로 남긴다.

## 요약

- 모델이 쓴 한 줄 요약에 **품질 문제**(대상 누락·오해 소지·문장 결함)가 있는지를 채점관(gemma4:12b)이 사람처럼 판정하는지 잰다.
- 측정 세트는 46건(자연 요약 31 + 결함을 심은 요약 15)이다. 검토자가 날조 측정에서 본 요약과 글자가 같거나 거의 같은 요약은 쓰지 않는다.
- 검토자 판정은 **채점 화면**으로 받는다. 측정 세트를 그대로 띄우고 검토자가 직접 고르므로, 원문을 옮겨 적는 단계가 없다(ISSUE-013 재발 방지).
- 기준: 자연 응답 일치율 85% 이상, κ 0.61 이상(조건부), 심은 결함 검출률 80% 이상, 거짓 경보율 15% 이하. 모두 충족하면 채택.

## 1. 왜 재는가

날조 측정([`judge_v15_results.md`](judge_v15_results.md))에서 판정이 갈린 자연 응답 6건 중 3건은 원문에 없는 사실이 아니라 **요약 품질**(오해 소지·핵심 누락·방향 오류)로 갈렸다. 요약만 보고 판단하는 개발자·QA를 잘못 이끄는 결함이라는 점에서 날조와 같은 무게를 가진다. 그래서 날조와 분리된 기준으로 정의하고, 채점관이 사람처럼 잡는지 잰다. 채택되면 라우팅에서 "요약을 사람이 다시 봐야 할 건"의 신호 후보가 된다.

## 2. 요약 품질의 정의 (검토자와 채점관에게 같은 문구로 준다)

질문: **이 요약 한 줄만 읽은 담당자가 이슈를 정확히 이해할 수 있는가?** 판정은 품질 문제 있음 / 없음이고, 있음이면 유형을 고른다(여러 개 가능).

| 유형 | 뜻 |
| :--- | :--- |
| Q1 대상 누락 | 무엇이·어디서가 빠져, 무엇에 대한 이슈인지 알 수 없다 |
| Q2 오해 소지 | 원문과 다른 뜻으로 읽힌다. 이슈의 성격이 바뀐 경우(건의 → 오류, 의심 → 확정 등)도 포함 |
| Q3 문장 결함 | 목적어·서술어가 빠지거나 문장이 어색해 뜻이 흐려진다 |

- **날조는 이번 판정 대상이 아니다.** 원문에 없는 사실이 보이면 메모에만 적고 나머지로 판정한다(날조는 따로 쟀다).
- **우선순위** — 단, 이슈의 성격을 바꾸는 서술(건의 → 오류, 의심 → 확정 등)은 날조가 아니라 Q2로 본다.
- 위 정의 문구(유형 표·날조 제외·우선순위·확신도)는 채점 화면, 기준 파일 주석, 채점관 프롬프트에 글자까지 같게 쓴다(테스트로 확인).
- 짧은 요약도 세 가지 문제가 없으면 "없음"이다.
- 확신도: 높음(다른 QA도 같게 볼 것 같다) / 보통(대체로 그렇지만 다르게 볼 수도 있다) / 낮음(경계에 있어 확신이 없다). 날조 측정에서 확신도가 63건 중 62건 "높음"이어서 정의를 붙였다.

## 3. 측정 세트 (46건, 리포트당 1건)

| 항목 | 내용 |
| :--- | :--- |
| 요약 출처 | 저장된 qwen2.5:7b 실행 기록(v1.4 개발용, M0·M1·M2, 여러 seed, 1·2회차)의 요약. 모델을 새로 실행하지 않는다. 채점관이 쓴 요약은 넣지 않는다 |
| 제외한 요약 | 검토자가 날조 측정에서 본 요약 63건과 그중 주입 요약의 원래 요약 20건을 기준으로, 같은 리포트에서 글자가 같거나 거의 같은(공백을 뺀 유사도 0.85 이상) 요약 |
| 제외한 리포트 | 17개 — 쓸 요약이 남지 않은 리포트 8개, 이 세트를 만드는 대화에서 언급된 리포트 8개(아래), 날조 측정에서 내용이 노출된 A06(ISSUE-012) |
| 자연 요약 | 31건. 리포트마다 고정 seed(1518)로 하나 |
| 결함 주입 | 15건(Q1·Q2·Q3 각 5건). 고정 seed로 리포트를 뽑고 원래 요약을 손으로 고쳤다. 날조는 넣지 않는다(새 낱말은 원문·원래 요약에 있거나 신고한 일반어만, v1.2 탐지기가 새 구체 사실을 잡으면 실패). Q2는 성격을 바꾸는 틀로만 만든다. 원래 요약부터 결함이 있는 후보는 같은 seed의 예비 후보로 바꿨고, 어느 것을 바꿨는지는 채점이 끝난 뒤 공개한다 |
| 개발용 자료 | 63건(리포트마다 측정 세트와 다른 요약 하나, 측정에서 뺀 리포트 포함) 중 결함 주입 6건(유형별 2건, 측정용 주입 리포트와 겹치지 않음) |
| 연습 문항 | 가상 리포트 5개. 측정 세트 밖. 지표에 쓰지 않는다 |

**계획 중 바뀐 점 (세트 커밋 전)**
1. 처음에는 채택 구성 seed 21 실행만 쓰려 했으나, 그 요약 63건 중 28건이 날조 측정 세트와 글자까지 같아 검토자의 앞선 판정·사후 의견이 따라올 수 있었다. 출처를 저장된 qwen2.5:7b 실행 기록 전체로 넓혔다.
2. 첫 세트(61건)를 만든 뒤 독립 검토에서, 본 요약과 글자만 조금 다른 요약이 약 17건 남는다는 지적이 나왔다. 완전 일치뿐 아니라 유사도 0.85 이상도 빼기로 했다.
3. 첫 세트를 만드는 대화에서 Claude가 주입 대상 리포트 번호와, 원래 요약에 결함이 있어 대상에서 뺀 리포트 번호를 검토자에게 적었다(A04·A20·S16·B09, S10·A18·B18·S04b). 그 8개 리포트는 결함 여부가 알려졌으므로 측정 세트에서 뺐다. 날조 측정에서 내용이 노출된 A06도 뺐다.
4. 첫 세트의 오해 소지(Q2) 주입 일부가 원문에 없는 상태를 단정해 날조와 겹친다는 지적이 나왔다. §2에 우선순위(성격을 바꾸는 서술은 Q2)를 넣고, Q2 주입은 성격을 바꾸는 틀로만 다시 만들었다.
5. 위 변경으로 주입 대상을 새 seed(1518)로 다시 뽑았다. 세부(어느 리포트에 무엇을 심었는지, 어느 후보를 바꿨는지)는 채점이 끝난 뒤 결과 보고서에 적는다. 첫 세트는 커밋하지 않았고 채점에 쓰지 않았다.

## 4. 채점 화면 (검토자 판정 받기)

| 항목 | 내용 |
| :--- | :--- |
| 구성 | 로컬 서버(`rater_server.py`, 표준 라이브러리) + 한 페이지(`rater_ui.html`). `127.0.0.1`에서만 열고 이 기기의 화면에서 온 저장만 받는다. 저장은 한 번에 하나씩, 임시 파일을 거쳐 쓴다 |
| 보여 주는 것 | 측정 세트 파일의 원문 칸과 요약 그대로. 서버는 정답 대응표·개발용 자료를 읽지 않는다 |
| 입력 | 판정(없음/있음), 유형(있음일 때 1개 이상), 확신도, 메모(선택). 누르는 즉시 `data/quality_v15/rater_answers_v15.json`에 저장, 중간에 꺼도 이어서 |
| 고치기 | 가능. 다른 값으로 다시 저장하면 이전 값을 고친 이력에 남긴다. 저장하지 않고 다른 문항으로 가면 확인을 묻는다 |
| 연습 | 측정 전에 연습 5문항. 참고 답(Claude 제안)은 그 문항을 저장한 뒤에만 서버가 내려 준다. 연습을 마치기 전에 채점으로 가려 하면 확인을 묻는다. 연습 답은 별도 파일 |

**채점 중 규칙**
1. Claude는 화면을 켜고 끄는 것과 진행 건수 확인만 한다. 채점이 끝날 때까지 문항 내용·개발 결과를 말하지 않는다(ISSUE-012 재발 방지).
2. 검토자는 채점이 끝날 때까지 `answer_key_v15.json`·`dev_set_v15.json`·`build_set.py`(주입 목록)·`tests/test_quality_v15.py`와 이 작업 중 대화의 도구 출력을 열어 보지 않는다. 결함을 심은 Claude는 어느 요약에 심었는지 알지만, 문항을 보여 주는 것은 화면이므로 질문 방식으로 영향을 줄 경로가 없다.
3. 채점 방법·기준에 관한 대화는 연습 문항까지 마치고, 채점 중에는 다른 기준을 꺼내지 않는다.

## 5. 채점관

- gemma4:12b, temperature 0·seed 1·think=False, JSON 출력(판정·유형·문제 문구), 읽지 못하면 1회 재요청. 날조 측정과 같은 채점관이며 이번에 바뀌는 것은 판정 대상(품질)뿐이다.
- 프롬프트(q1)는 **개발용 자료로만** 다듬는다. 정의(§2)는 검토자 화면과 같은 문구를 쓴다. 확정한 프롬프트의 지문과 모델 digest를 개발용 결과에 남기고, 측정 때 같은지 확인한다.
- 채점관 실행·지표 계산 도구(`src/triage_eval/pipeline/quality.py`)는 검토자 채점이 시작된 뒤, 측정 전에 커밋한다. 측정은 한 번만 하고, 결과를 출력보다 먼저 저장한다(ISSUE-014).

## 6. 지표와 판단 기준 (사전 등록)

| 지표 | 계산 | 기준 |
| :--- | :--- | :--- |
| 자연 응답 일치율 | 자연 31건 중 검토자와 채점관의 판정(있음/없음)이 같은 비율 | 85% 이상 (27건 이상) |
| 자연 응답 κ | 검토자 대 채점관 Cohen κ | 0.61 이상. 검토자의 "있음"이 5건 미만이면 기록만 |
| 심은 결함 검출률 | 결함 주입 15건 중 채점관이 "있음"으로 본 비율(유형 무관) | 80% 이상 (12건 이상) |
| 거짓 경보율 | 검토자가 "없음"으로 본 자연 응답 중 채점관이 "있음"으로 본 비율 | 15% 이하 |
| 기록 | 유형별 일치, 검토자의 주입 검출률, 확신도별 일치율, 채점관 출력 읽기 실패 | 판정에 쓰지 않음 |

- 기준값과 같으면 충족. 판정에 쓰는 지표가 모두 충족하면 **채택**, 하나라도 못 하면 **미채택**.
- 품질은 날조보다 판단 폭이 넓어 기준을 날조 측정(90%·90%·10%)보다 한 단계 느슨하게 두었다. 일치율 85%는 v1.5 라벨 일치율 기준과 같다.
- 채점관 출력을 두 번 읽지 못한 건은 불일치·놓침·거짓 경보로 센다. 실행 도중 모델 재로드는 측정 무효다.

## 8. 한계

- **사람 채점자가 1명이다.** 날조 측정의 가장 큰 한계와 같다. 검토자 결정(2026-10-29)으로 혼자 채점하고, 결과 해석에서 이 점을 먼저 적는다.
- **리포트는 날조 측정과 같은 63개 중 46개다.** 요약은 새것이지만 리포트 내용은 검토자가 이미 읽었다.
- **세트가 작다.** 자연 응답 1건이 일치율 약 3.2%p다. κ는 검토자의 "있음"이 적으면 크게 흔들린다.
- **개발용 자료도 같은 리포트를 쓴다.** 요약은 측정 세트와 다르지만, 프롬프트가 같은 원문에 맞춰질 수 있다.
- **결함은 Claude가 손으로 심었다.** 실제 품질 결함과 모양이 다를 수 있다. 주입 요약과 자연 요약의 평균 길이는 23.9자 대 26.8자로 맞췄다(날조 측정은 39자 대 25자). "~다"로 끝나는 요약은 주입 1/15, 자연 3/31이다. Q1은 대상을 지우는 대신 길이를 유지하는 방식으로 흐렸다. 명사형 종결(-임·-음·-함·-됨)은 주입 3/15, 자연 7/31이다.
- **자연 요약에 날조가 섞여 있을 수 있다.** 판정 대상이 아니라고 화면에 적었지만, 날조가 품질 판단에 영향을 줄 수 있다.
- **일부 주입은 정의의 문턱 근처일 수 있다.** 대상을 흐리기만 한 Q1처럼, 채점관이 "없음"이라고 해도 틀렸다고 보기 어려운 문항이 있을 수 있다. 검출률은 검토자의 주입 검출률과 함께 해석한다.
- **같은 세트는 다시 쓰지 않는다.** 측정 뒤에는 이 46건을 다른 측정에 쓰지 않는다.
